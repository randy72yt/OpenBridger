## 一、适用范围

本政策说明 OpenBridger 在提供网站、控制台、API 转发、凭证管理、用量查询及相关服务时对个人信息的处理方式。

第三方模型服务商及其他独立服务可能按照各自政策处理信息。平台应在实际接入情况下说明相关服务商、处理目的及必要的数据流向。

本平台仅面向非中国大陆地区用户。请您自行确认访问及使用本服务符合所在地适用法律法规、上游服务条款及平台规则；因违反相关规定产生的责任，依法由相应责任主体承担。公开页面不陈述运营所在地，也不使用参考网站的备用域名。

运营主体已定为 **OpenBridger**。

**待确认：**适用的数据保护制度。

## 二、可能涉及的信息

以下为待核实的数据清单，正式版本仅保留实际处理的项目。

| 数据类别 | 可能涉及的信息 | 主要用途 |
| --- | --- | --- |
| 账号资料 | 用户名、邮箱、昵称、账号状态及权限信息 | 创建和管理账号 |
| 认证与安全信息 | 密码哈希、已启用的 OAuth 绑定信息、二次验证或 Passkey 状态、登录记录 | 身份验证和账号保护 |
| 网络与访问记录 | IP、User-Agent、请求时间、响应状态及必要设备信息 | 服务交付、故障排查和安全防护 |
| API 调用元数据 | 模型、请求标识、用量、消耗、耗时、状态及必要错误信息 | 请求处理、计费、统计和排障 |
| 请求与任务内容 | 提示词、上下文、文件及模型输出 | 完成用户发起的调用或任务 |
| 交易记录 | 已开放收费功能下的订单、金额、支付状态和退款记录 | 交付、对账及争议处理 |
| 主动提交的支持信息 | 用户提供的问题说明、反馈及经过必要脱敏的材料 | 客户支持 |

不应要求用户提交与服务无关的敏感信息。支持材料应避免包含可用 API Key、密码、完整支付凭证或无关个人信息。

## 三、信息使用目的

按实际启用的功能，信息处理可能用于：

- 创建、验证和维护账号，保存必要偏好；
- 转发模型请求、返回响应和处理异步任务；
- 计算调用用量、展示记录以及处理已开放的订单和账务；
- 排查故障、防止账号盗用、攻击与滥用；
- 处理用户反馈、数据权利请求及必要服务通知；
- 履行适用法律规定的义务。

**待确认：**逐项对应实际处理依据。可选统计、营销和其他非必要用途需单独核实，不因参考政策列举而视为已获授权。

## 四、API 请求内容与日志

完成模型调用通常需要将相应请求内容传输给所选上游服务。平台应明确区分请求转发所需的临时处理、调用元数据记录以及完整内容的持久化存储。

**待确认：**完整请求和响应是否落盘、错误日志是否可能包含内容、任务文件保存位置、管理员访问范围、内容审阅条件及是否存在用户主动启用的存储功能。核实前不作“零日志”或“不保存请求内容”的承诺。

用户应避免提交无关个人信息、生产密钥或未经授权的保密材料；使用学校或团队数据时，应遵守相应授权要求。

## 五、Cookie 与本地存储

登录会话、语言和主题偏好可能使用 Cookie 或本地存储。用户可以通过浏览器管理这些数据，删除必要数据可能导致退出登录或偏好重置。

**待确认：**实际使用的存储项目、用途和期限，以及是否启用分析工具。参考站的 Umami、Google Analytics 和统计域名不直接加入本政策。非必要技术如需同意，应有实际可用的选择和撤回方式。

## 六、共享与委托处理

应仅在服务所需范围内向实际使用的服务商提供必要信息，例如上游模型、基础设施、邮件、身份认证和已启用的支付服务商。

**待确认：**具体服务商清单、数据类别、使用目的、处理地区和双方责任。第三方独立处理规则应提供可查询的说明。

拟采用的原则是不得将用户个人信息作为商品出售；正式发布前应核实实际商业及统计集成是否符合这一表述。

## 七、支付信息

如果开放付费服务，应说明平台与支付处理方分别处理哪些信息，包括订单元数据及支付验证信息。

**待确认：**实际支付渠道和数据流向。未完成核查前，不声明已接入 Waffo Pancake，也不对支付卡信息的存储情况作未经验证的断言。

## 八、跨境处理

模型服务、托管及其他供应商可能位于用户所在地区以外。正式版本应说明实际接收地区、接收方和处理目的，并按适用要求落实必要手续和保障。

**待确认：**部署地区、上游路由及跨境安排。不将“继续使用”概括为所有跨境处理的有效授权，也不声明尚未签署的标准合同或数据处理协议已存在。

## 九、保存与删除

保存期限应与用途、账务、安全和适用法律要求相匹配。无需继续保留的信息应按实际可执行流程删除或匿名化。

| 数据类别 | 保留期限和到期处理 |
| --- | --- |
| 账号及认证资料 | 待确认，包括注销后的处理 |
| API 元数据、错误与安全日志 | 待确认，包括清理任务与例外保留 |
| 完整请求、响应与任务文件 | 待确认是否持久保存；如保存需列明期限 |
| 订单与账务记录 | 待确认，结合实际支付和法定义务 |
| 客服材料 | 待确认 |
| 备份副本 | 待确认轮换周期及删除请求的同步方式 |

参考站的数字保留期限不是 OpenBridger 的现行规则。

## 十、安全保护与事件处理

正式说明应反映实际部署的传输保护、密码哈希、权限隔离、日志脱敏、备份及访问审计措施。

**待确认：**生产 HTTPS、密钥存储和访问范围、备份恢复能力、告警与事件响应流程。安全事件通知应按照适用要求确定对象、条件和时限，不能直接复制参考站的统一 72 小时承诺。

用户也应保护账号和凭证，发现异常时及时撤销相关 Key 并联系平台。

## 十一、用户权利

在适用法律范围内，用户可请求了解信息处理情况、访问、更正、删除或获取相关数据，并对基于同意的非必要处理撤回授权。

平台受理请求时应进行与风险相称的身份核验，避免泄露他人信息。依法必须保留的数据及备份处理限制，应在必要时说明。

**待确认：**申请入口、受理人员、可提供的数据范围、响应时限与投诉途径。联系方式预设为 `support@openbridger.com`（占位，正式发布前须确认可收信）。

## 十二、服务通知与营销

应区分账号安全、订单等必要服务通知和可选营销信息。若以后启用非必要邮件或推广，应说明实际授权与退订方式。

**待确认：**是否开展营销、邮件供应商及退订流程。不预设相关能力已经存在。

## 十三、未成年人

OpenBridger 的目标用户包含学生，但学生不必然达到成年年龄。

**待确认：**最低使用年龄、是否接纳未成年人，以及相应监护人授权和保护安排。正式政策和注册流程应保持一致，不能直接移植参考站的成年人限定。

## 十四、政策更新与联系

正式版本应列明版本和生效日期，并对重大变更作适当告知。涉及需单独授权的数据用途，不以单纯继续访问代替必要授权。

运营主体：OpenBridger。隐私联系邮箱与受理渠道：`support@openbridger.com`（预设占位，须在域名邮箱可收信后确认）。
