# 分组与线路

分组决定这把密钥能用哪些模型、走到哪类线路、按哪套倍率计费。你不需要知道上游渠道的名字。选模型时以模型广场里、当前分组下看得到的 ID 为准。

## 密钥上的分组

| 填法 | 结果 |
| --- | --- |
| 留空 | 使用账户自己的分组。 |
| 指定一个分组 | 该分组必须在你的可用分组里。否则 `403`，文案是「无权访问某分组」。分组已被弃用时也是 `403`，「分组某已被弃用」。 |
| `auto` | 按你保存的顺序尝试多个分组。打开「跨分组重试」后，当前分组没有可用线路或调用失败时，会按顺序试下一个。 |

分组名称和倍率由运营配置。文档里没有「标准 / 优选 / 尊享」这类固定商品名。广场和密钥页面上出现的名字才是真的。

## 使用时

- 客户端的模型列表应来自当前密钥能访问的范围。`GET /v1/models` 就是这个范围。
- 同一个模型 ID 在不同分组的价格和稳定性可以不同。换分组等于换计价，先看广场。
- 出现 `503` 且文案含「无可用渠道」时，先核对模型和分组，不要反复换密钥。
- 团队里记下每个项目用的分组和模型 ID，排障时少一轮猜测。
