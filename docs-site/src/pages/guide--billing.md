# 额度与计费

钱包里的余额是调用额度。模型广场上的价格决定一次请求怎么折算成额度。日志里的那一行是结算结果。

## 额度单位

钱包、使用日志和模型广场都按人民币（¥）显示。内部记账仍是整数额度，默认 **500000 额度 = 1 美元**，页面再把它显示成人民币。支付金额、余额和单次消耗以页面上的人民币数字为准，不要自己乘汇率。

## 一次请求怎么扣

<div class="steps"><div class="step"><strong>预扣</strong><p>网关按模型价格估算本次需要的额度。钱包或订阅不够时，请求直接失败，状态码 <code>403</code>，<code>code</code> 为 <code>insufficient_user_quota</code>，文案含「用户额度不足」或「预扣费额度失败」。失败时不会去上游。</p></div><div class="step"><strong>调用</strong><p>预扣成功后才转发。请求失败时退回预扣。</p></div><div class="step"><strong>结算</strong><p>成功后按实际用量计算应扣额度。比预扣多就补扣，比预扣少就退回。使用日志里的消耗是结算后的数。</p></div></div>

默认扣费偏好是「优先订阅」（`subscription_first`）。没有有效订阅时扣钱包。有订阅时先扣订阅，是否在不足时回退到钱包取决于该订阅是否允许，见 [订阅套餐](/guide/account/subscriptions/)。钱包里还可以改成「优先钱包」「仅用订阅」或「仅用钱包」。

密钥还可以有自己的剩余额度。密钥额度用尽是 `401`「无效的令牌」，和钱包不足的 `403` 不是同一条错误。

## 哪些数量会影响金额

- 输入、输出和缓存 token。上下文越长，输入部分越高。Agent 会把历史和工具结果一再送回去。
- 分组倍率。分组不同，同一模型的结算可以不同。
- 图像张数、音视频时长、分辨率等，只在该模型按这些单位计价时计入。异常大的张数或时长会在校验时被拒绝，而不是记成一笔负数。

模型广场没有写出的附加项，不要自行假设已经在计费。以该模型页面和这次日志为准。

## 怎么核对一笔消耗

<div class="steps"><div class="step"><strong>单独一把密钥</strong><p>测试工具不要和生产共用密钥。</p></div><div class="step"><strong>记下时间</strong><p>发请求前看一眼时钟。</p></div><div class="step"><strong>打开使用日志</strong><p><a href="{{CONSOLE_URL}}/usage-logs">使用日志</a>按时间、密钥和模型筛选。绘图、视频等异步任务可能在任务日志，而不是对话日志。</p></div><div class="step"><strong>看模型和分组</strong><p>确认扣的是你选的模型 ID，而不是客户端悄悄换成的另一个名字。</p></div></div>

消耗比预期高时，先看是不是整段历史被重复发送，或 Agent 连续调用了工具。日志里的 token 数是结算依据。

## 充值以后额度从哪来

在线充值和兑换码都加到钱包。规则、最低金额和退款见 [充值与兑换](/guide/account/redeem/)。

<div class="callout warning"><strong>不要用文档数字对账</strong><p>模型单价以模型广场为准。注册没有赠送额度。最低充值额以钱包页面为准。对账时看确认页和使用日志里的人民币金额。</p></div>
