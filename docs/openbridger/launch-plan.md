# OpenBridger 上线实施计划

最后更新：2026-09-20

## 总体原则

先确定首发边界，再准备外部账号和生产环境，随后接入上游与价格，最后执行完整验收。每个阶段的输出必须可复查，并更新[项目档案](./project-profile.md)和[生产验收](./production-acceptance.md)。

## Release 1 待办总览

第一个版本限定为**少量受邀用户试运行文本模型**，暂不开放在线支付，价格变更继续由管理员审核。备用渠道是内部路由配置，不作为对外宣传承诺；启用自动切换时须验证切换和单次结算。`PRICING_CONTROL_ENABLED=true` 只是下表中的一项配置，不构成发布验收。

| 顺序 | 必做工作 | 完成标准 | 当前状态 |
| --- | --- | --- | --- |
| 1 | 锁定首发范围：注册方式、是否开放在线支付、用户规模、首批文本模型、是否启用内部备用路由 | 更新 DEC-001/003/004 和首发模型清单；关闭的功能在页面与接口均不可用 | 部分确认：邀请制、文本模型、关闭在线支付；候选模型已选 |
| 2 | 修复定价管理可观测性：展示同步 warnings/失败渠道，补存量 NULL 倍率回归和三库 CI 防跳过检查 | 管理员能看到被跳过模型及原因；自动测试能明确证明三库都执行 | 代码与本地验收已完成；待 CI 执行确认 |
| 3 | 准备真实上游并定价：至少一个可用 Key；启用备用路由时需第二渠道；配置模型映射、额度、毛利和审核流程 | 首批模型流式/非流式调用、实际扣费对账通过；启用自动切换时验证切换与不重复结算 | 待实施 |

| 5 | 完成账号与反滥用流程：SMTP、验证/找回、注册限制、管理员 MFA/Passkey | 适用 AUTH-001～004 通过，公开注册时反自动化保护生效 | 待实施 |

执行顺序以依赖为准：第 1 项先确定发布边界；第 2 项可与生产资料准备并行；第 3～8 项完成后再执行第 9 项。未开放在线支付不能直接把支付流程视作通过，必须验证其入口与接口均已关闭。生产试运行开始后按阶段 8 连续观察 3～7 天，再决定是否扩大开放。

### README 已列、但不一定阻断 Release 1 的事项

- **按次计费的绘图模型动态定价**：若首版只开放文本模型，按 [规格](./spec-per-request-pricing.md) 排入后续版本；若首版销售绘图能力，则升级为发布前必做并验收。
- **第二上游与故障转移**：这是内部可靠性能力，不需要对用户作宣传承诺。首版若启用自动切换，第二渠道和故障转移验收是发布前必做；若暂以单渠道试运行，可延后，页面不得宣传自动故障转移或可用性保证。
- **EDGE-001 零成本报价语义**：当前实现拒绝生成调价方案。首版继续采用此保守行为，产品需在发布范围记录中追认；若要允许零成本模型，须先设计保护价和对应验收。
- **区分过期方案错误原因**：当前错误已附带部分具体文字，但仍共用 `ErrPricingProposalStale`；可以在后续版本拆分稳定错误码。
- **存量 NULL 倍率与 CI 防跳过**、**同步 warnings 展示**已纳入上表第 2 项，不再作为模糊遗留项。

第 2 项本地复验（2026-09-20）：前端类型检查、定价控制组件测试（5 条）和涉及文件 lint 通过；真实 SQLite、MySQL 8.0、PostgreSQL 17 矩阵均通过，建议输入/输出售价三库一致（3.28125000 / 16.40625000）。测试还验证旧记录 NULL 倍率不会被猜测，补入实际倍率后恢复生成方案。CI 设置 `PRICING_DB_MATRIX_REQUIRED=true`，缺少任一 DSN 将直接失败。远端 CI 尚待本次提交推送后确认。

发布准备复验（2026-09-20）：从当前源码生成前端并重建本地 Docker 容器，`/api/status` 正常；`compose.release.yml` 配置解析和本地发布镜像构建通过。`OPENBRIDGER_ONLINE_PAYMENT_ENABLED=false` 时，钱包页不显示充值/套餐，服务端拒绝创建订单；支付开关测试、受影响 Go 包测试、前端类型检查、钱包现有测试和生产前端构建通过。Docker 构建上下文已排除 `.env`、运行数据与临时目录。生产 DNS 查询尚无 A 记录，现有上游凭证读取模型/价格接口均返回 403，且本地数据库尚无上游渠道；因此真实模型与成本验收尚未开始，不能将候选清单标为已上线。

### 首批文本模型候选（2026-09-20）

先覆盖大学生日常问答、开发者编码与高阶推理，控制在 10 个公开模型。官方型号和生命周期已核对；CodeGo/DDD 的可用性、实际模型 ID、价格和扣费仍须在上架前逐个复核。未通过验证的条目先隐藏，不用旧模型或模糊别名自动顶替。

| 分层 | 公开模型 ID 候选 | 用户场景 | 上架前重点 |
| --- | --- | --- | --- |
| 日常低成本 | `gpt-5.6-luna` | 轻量问答、学习辅助 | 确认 CodeGo/DDD 同名模型和稳定性 |
| 日常低成本 | `claude-haiku-4-5` | 快速文本、简单代码 | 确认上游别名对应官方版本及退役日期 |
| 日常低成本 | `gemini-3.8-flash` | 通用问答、长文处理 | 9 月调研仅 DDD 有正常报价，复核现价与接口 |
| 日常低成本 | `deepseek-flash` | 中文、代码、低成本试用 | 官方现用 ID；验证上游是否仍只提供旧的 `deepseek-v4-flash` 别名及真实计费 |
| 主力 | `gpt-5.6-terra` | 通用开发与复杂任务 | 对照渠道模型清单、流式与非流式响应 |
| 主力 | `claude-sonnet-5` | 编码、写作、长任务 | 验证上游分组倍率，按实际上游账单定价 |
| 主力 | `deepseek-v4-pro` | 中文推理、代码 Agent | 验证实际上游版本和阶梯计费 |

依据：[OpenAI 模型目录](https://platform.openai.com/docs/models)、[Claude 模型目录](https://platform.claude.com/docs/en/models/overview)、[Gemini 模型目录](https://ai.google.dev/gemini-api/docs/models)、[DeepSeek 模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)，以及 2026-09-08 的 CodeGo/DDD 渠道调研。`GPT-6 Astra` 暂不列入：调研中有该名称，但目前未从 OpenAI 官方 API 模型目录核实相同公开 ID。Grok、Kimi、GLM 可在这 10 个型号实际跑通后作为下一批加入。

受邀试运行期间，额度建议由管理员按账户发放固定试用额度，并设置单用户上限；具体额度数值、发放入口与撤销方式在测试扣费后确定。不要将 CodeGo 显示的“免费”报价直接视为可持续零采购成本。
