# OpenBridger 上线实施计划

最后更新：2026-09-21

## 总体原则

先确定首发边界，再准备外部账号和生产环境，随后接入上游与价格，最后执行完整验收。每个阶段的输出必须可复查，并更新[项目档案](./project-profile.md)和[生产验收](./production-acceptance.md)。

## Release 1 待办总览

第一个版本限定为**少量受邀用户试运行文本模型**，暂不开放在线支付，价格变更继续由管理员审核。备用渠道是内部路由配置，不作为对外宣传承诺；启用自动切换时须验证切换和单次结算。`PRICING_CONTROL_ENABLED=true` 只是下表中的一项配置，不构成发布验收。

### README 已列、但不一定阻断 Release 1 的事项

- **按次计费的绘图模型动态定价**：若首版只开放文本模型，按 [规格](./spec-per-request-pricing.md) 排入后续版本；若首版销售绘图能力，则升级为发布前必做并验收。
- **第二上游与故障转移**：这是内部可靠性能力，不需要对用户作宣传承诺。首版若启用自动切换，第二渠道和故障转移验收是发布前必做；若暂以单渠道试运行，可延后，页面不得宣传自动故障转移或可用性保证。
- **EDGE-001 零成本报价语义**：当前实现拒绝生成调价方案。首版继续采用此保守行为，产品需在发布范围记录中追认；若要允许零成本模型，须先设计保护价和对应验收。
- **区分过期方案错误原因**：当前错误已附带部分具体文字，但仍共用 `ErrPricingProposalStale`；可以在后续版本拆分稳定错误码。
- **存量 NULL 倍率与 CI 防跳过**、**同步 warnings 展示**已纳入上表第 2 项，不再作为模糊遗留项。

第 2 项本地复验（2026-09-20）：前端类型检查、定价控制组件测试（5 条）和涉及文件 lint 通过；真实 SQLite、MySQL 8.0、PostgreSQL 17 矩阵均通过，建议输入/输出售价三库一致（3.28125000 / 16.40625000）。测试还验证旧记录 NULL 倍率不会被猜测，补入实际倍率后恢复生成方案。CI 设置 `PRICING_DB_MATRIX_REQUIRED=true`，缺少任一 DSN 将直接失败。远端 CI 尚待本次提交推送后确认。

发布准备复验（2026-09-20）：从当前源码生成前端并重建本地 Docker 容器，`/api/status` 正常；`compose.release.yml` 配置解析和本地发布镜像构建通过。`OPENBRIDGER_ONLINE_PAYMENT_ENABLED=false` 时，钱包页按接口状态隐藏充值/套餐，服务端拦截订单创建；支付开关测试、受影响 Go 包测试、前端类型检查、钱包现有测试和生产前端构建通过。Docker 构建上下文已排除 `.env`、运行数据与临时目录。生产 DNS 查询尚无 A 记录，现有上游凭证读取模型/价格接口均返回 403，本地数据库尚无上游渠道，用户协议与隐私政策接口返回空正文；因此真实模型、成本和法律验收尚未开始，不能将候选清单标为已上线。
