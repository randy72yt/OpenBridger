# OpenBridger 上线实施计划

最后更新：2026-09-09

## 总体原则

先确定首发边界，再准备外部账号和生产环境，随后接入上游与价格，最后执行完整验收。每个阶段的输出必须可复查，并更新[项目档案](./project-profile.md)和[生产验收](./production-acceptance.md)。

## 阶段 0：建立项目记录与验收基线

状态：**已完成**

- [x] 建立项目控制中心。
- [x] 建立产品、架构、决定、依赖、秘密和风险登记骨架。
- [x] 建立生产验收用例和发布阻断规则。
- [x] 建立分阶段上线计划。

完成标准：后续工作有唯一记录入口、状态定义和证据格式。

## 阶段 1：确认首发范围

状态：**待确认**

依次确认：

1. 邀请制试运行还是公开注册。
2. 第一阶段是否开放在线支付。
3. 首批用户规模和预计日调用量。
4. 首批模型清单，建议控制在 10～20 个。
5. CodeGo、DDD 的主备关系和各自充值折扣。

输出：更新 DEC-001、DEC-003、DEC-004，形成首发范围清单。

## 阶段 2：准备生产账号与资料

状态：**待实施**

- [ ] 获取 CodeGo、DDD 生产账号、API Key、价格来源和调用限额。
- [ ] 确定生产数据库、Redis、服务器和备份存储。
- [ ] 准备 SMTP 发件域名和账号。
- [ ] 如开放支付，准备商户生产/沙箱资料和 Webhook 配置。
- [ ] 确定客服、隐私、安全和商务联系方式。

输出：外部依赖登记完整；秘密只进入受控密钥存储。

## 阶段 3：生产部署基线

状态：**待实施**

- [ ] 创建 staging 和 production 环境。
- [ ] 配置 PostgreSQL/MySQL、Redis 和高强度会话密钥。
- [ ] 配置 `openbridger.com` 与 `docs.openbridger.com` 的 DNS、TLS 和反向代理。
- [ ] 启用生产 Secure Cookie、可信 Origin 和可信代理。
- [ ] 限制数据库和 Redis 网络访问。
- [ ] 建立数据库备份、日志轮转、健康检查和基础告警。

完成标准：OPS-001 至 OPS-004 在 staging 通过。

## 阶段 4：上游渠道与价格

状态：**待实施**

- [ ] 配置 CodeGo、DDD 渠道和模型映射。
- [ ] 完成首批模型的流式、非流式和工具调用验证。
- [ ] 完成主渠道失败到备用渠道的切换验证。
- [ ] 实现两个上游的价格采集适配器。
- [ ] 导入采购成本，设置目标/最低毛利并发布首批价格。
- [ ] 对比实际上游账单和 OpenBridger 扣费。

完成标准：RELAY-001 至 RELAY-004、BILL-001 至 BILL-005 通过。

## 阶段 5：注册、邮件和反滥用

状态：**待实施**

- [ ] 配置 SMTP 并验证邮件送达。
- [ ] 配置邮箱验证、密码恢复和 Turnstile。
- [ ] 根据首发范围启用邀请制或公开注册。
- [ ] 检查管理员账号的 MFA/Passkey 和恢复方式。

完成标准：适用的 AUTH-001 至 AUTH-004 通过。

## 阶段 6：支付与正式协议

状态：**待确认**

如果首发关闭在线支付：隐藏支付入口，记录本阶段支付用例“不适用”，明确管理员充值流程。

如果首发开放在线支付：

- [ ] 确认币种、最低充值、套餐、退款和争议规则。
- [ ] 完成真实商户创建订单、回调、幂等、退款和对账测试。
- [ ] 根据实际供应商和数据流完成用户协议与隐私政策。
- [ ] 增加协议版本接受记录。

无论是否开放支付，都必须：

- [ ] 确认服务对象、最低年龄和联系方式。
- [ ] 删除法律文本全部待定标记。
- [ ] 发布正式版本号和生效日期。

完成标准：LEGAL-001 通过；开放支付时 PAY-001 至 PAY-003 通过。

## 阶段 7：发布候选版本与全流程验收

状态：**待实施**

- [ ] 整理当前修改，确认无密钥或临时数据进入版本库。
- [ ] 建立发布分支或发布候选标签，执行 CI。
- [ ] 部署 staging 发布候选版本。
- [ ] 按生产验收文档执行所有适用 P0 用例。
- [ ] 执行备份恢复和版本回滚演练。
- [ ] 修复失败项并重新执行原用例。

完成标准：适用 P0 全部通过，签署表完成，生产发布包可回滚。

## 阶段 8：邀请制生产试运行

状态：**待实施**

- [ ] 先开放给少量测试用户。
- [ ] 每日检查上游成功率、余额、毛利、错误率和用户反馈。
- [ ] 人工审核所有价格变化。
- [ ] 验证支持、退款或管理员充值流程。
- [ ] 记录并修复试运行问题。

建议试运行至少 3～7 天，再决定是否开放注册或扩大规模。

## 下一步

从阶段 1 开始。首先确认：**第一阶段采用邀请制时，是否同时开放在线支付。** 这一决定会影响支付、协议、邮件、风控和验收范围。
