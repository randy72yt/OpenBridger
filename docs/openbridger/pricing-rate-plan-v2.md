## 3. 现在的费率错在哪

### 3.1 三层价格互相打架

| 层 | 值（以 `gpt-5.6-luna` 为例） | 问题 |
|---|---|---|
| 真实成本 | $0.0162/M | — |
| 动态定价已发布价 | $0.660/M（成本 ×3，毛利 66.67%） | 2026-11-02 已 `published`，但**没写回计费** |
| 计费实际用价 | $0.20/M（`billing_expr` 里的官方挂牌） | 没跟随成本 |
| 用户实际付费 | **$0.40/M**（`GroupRatio=2` 再翻倍） | 双重叠加 |

### 3.2 后果：每个模型的加价倍数完全不同

| 模型 | 我们收费 | 真实成本 | 倍数 |
|---|---|---|---|
| gpt-5.6-luna（83% 流量） | $1.164 | $0.0145 | **80×** |

| gpt-6-astra | $0.0608 | $0.0039 | 15.6× |

同一张价目表里，便宜模型被加价 80 倍、贵的模型只加 5–10 倍 —— 用户觉得"便宜的也不便宜，贵的更离谱"，投诉与流失都从这里来。

### 3.3 `GroupRatio=2` 没有任何业务依据

`{"default":2,"svip":2,"vip":2}`：所有分组统一在挂牌价上翻一倍。这是历史遗留，不是定价决策。

## 4. 新费率规则

### 4.1 规则

```
售价 = max(官方挂牌价 × 0.6, 真实成本 × 2.5)      # 输入 / 输出 / 缓存读 三档分别算
GroupRatio = 1
```

- **官方 6 折**是给用户的价值主张，也是最容易讲清楚的一句话；
- **成本 × 2.5 兜底**保证任何模型毛利率不低于 60%；
- 48 个模型里 **42 个**按 6 折落地（上游折扣 2%–15%），只有 6 个因上游无折扣走兜底。

## 5. 积分制（对外单位）

### 5.1 定义

- **1 积分 = ¥0.01（1 分钱）用量**，后台 = 694.444 额度；
- `¥10 = 1,000 积分 = 694,444 额度`（与现有 `credit_quota` 逻辑天然一致）；
- 用户侧展示：`1,000 积分 ≈ 1,790 次调用`，消耗时显示 `本次 0.7 积分`。

不再出现 694,444 这种数字，也不会再有人问"充 10 元为什么得 69 万"。

### 9.2 单价换算 → 不能对标

| 口径 | ¥ / $1 挂牌额度 | 占挂牌 |
|---|---|---|
| DDD 混合号池 | ¥0.145 | **2.0%** |
| DDD Pro 号池 | ¥0.193 | 2.7% |
| **我们的采购价**（offers × ugr） | **¥0.707** | **9.8%** |
| 方案 v2 售价 | ¥4.49 | 62% |

**关键事实：我们从 DDD 买 API 的价格，是 DDD 自己零售号池的 4.9 倍。**

这不是定价问题，是采购结构问题 —— 号池卖的是"自家账号的剩余产能"，我们买的是"API 转售权"，两者成本基数不同。因此：

- **不要用 DDD 号池价格做价格锚**：无论我们把 ¥2.49/M 降到 ¥1.42 还是 ¥0.7，相对它仍是 18–31 倍，降到位就亏；
- **真正的对标物是积分制竞品**（¥0.0053/次 ≈ ¥2.35/M）：v2 的 ¥2.49/M 正落在同一区间；
- 要抢价格敏感用户，唯一的办法是**向 DDD 谈 API 渠道价，把 9.8% 打到 3% 以内** —— 商务动作，不是定价动作。

**结论：价格维持 v2 不变；这张图的参考价值在套餐形态，不在价格。**

### 9.5 新用户赠送：会不会被薅秃

单账号成本 = 赠送积分 × 成本占比（v2 下 15.7%）：

| 赠送 | 价值 | 我们的成本 |
|---|---|---|
| 100 积分 | ¥1 | **¥0.16** |
| 500 积分 | ¥5 | **¥0.79** |
| 1,000 积分 | ¥10 | ¥1.57 |

1,000 个假号刷 500 积分 = **¥790**。不会"薅秃"，但会持续漏。

**建议：不做无条件赠送**（维持 `QuotaForNewUser=0`），改成：

1. **首充满 ¥10 送 300 积分**（¥3 用量，成本 ¥0.47，占首单收入 4.7%）—— 把获客成本和真金白银绑在一起，刷号无收益；
2. 赠送积分 **30 天过期**、仅限标准池；
3. 已有 Turnstile + 邮箱验证足够挡脚本；再加"同 IP 24h 内最多 3 个注册"即可。

### 9.6 无折扣 6 个模型的处置（原问题 1）

这 6 个（`deepseek-v4-pro`、`deepseek-v4.1-flash`、`glm-5.2`、`glm-5.3`、`kimi-k3`、`gpt-6-luna`）的上游倍率是 0.9–1.1，等于**进货价就是挂牌价，没有折扣空间**。按"官方 6 折"卖等于卖一个亏 40%。

三条路：

| 选项 | 结果 | 评价 |
|---|---|---|
| A 按成本 2.5 倍卖 | 售价达挂牌 225%–250%，价目表自相矛盾 | 不推荐 |
| B 下架 | 只卖 42 个有折扣的 | **推荐**：这 6 个合计仅 35 次调用（8%），损失接近零 |
| C 保留但只走企业合同 | 不对公开价目表 | 备选 |

推荐 **B**，并在模型选择器里去掉，避免用户拿 DeepSeek 官方价来比价。

## 11. 上游资料维护：这是当前最大运营风险

结论：**机制已经存在，缺的是最后一公里的校验。** 生产环境已开 `PRICING_CONTROL_ENABLED=true`，每 12 小时同步一次上游报价，但发布出去的价和实际计费的价有 26% 对不上，无人发现。

### 11.1 现有链路（全部已上线）

| 步骤 | 实现 | 节奏 | 状态 |
|---|---|---|---|
| ① 采集上游报价 | `service/pricing_offer_sync.go`，写 `upstream_model_offers` | 每 720 分钟 | ✅ 48 条，最近同步 11-05 06:38 |
| ② 成本校准 | `service/pricing_calibration.go`，72h 窗口 / 5 样本 / 离散度 15% | 每 720 分钟 | ✅ 已开 |
| ③ 生成调价提案 | `model_price_proposals` | 随同步 | ✅ 164 条（130 published / 32 pending） |
| ④ 发布到计费 | `PublishPricingProposal` → `UpdateModelPricing` | 随同步（auto=false） | ⚠️ 部分失效 |
| ⑤ 对外展示同步 | 套餐文案 / 价目页 / 模型选择器 | 手工 | ❌ 无联动 |

### 11.2 实测断点：9 / 34 个模型的发布价与计费不符

把 130 条 `published` 提案的 `proposed_input_price` 与 `billing_setting.billing_expr` 里实际的 `p *` 系数逐条比对：

| 模型 | 提案价 | 计费实际 | 差异 |
|---|---|---|---|
| gpt-5.6-luna | $0.6601 | **$0.2000** | 计费只有提案的 30% |
| gpt-6-astra | $4.5005 | **$10.00** | 计费是提案的 2.2 倍 |
| gpt-5.6-sol | $2.2502 | $5.00 | 2.2 倍 |
| gpt-5.6-terra | $0.9001 | $2.00 | 2.2 倍 |
| gpt-6-sol | $0.9001 | $2.00 | 2.2 倍 |
| gemini-3.1-pro-preview | $1.8002 | $2.00 | 1.1 倍 |
| gemini-2.5-flash | $0.2700 | $0.30 | 1.1 倍 |
| gpt-5.3-codex-spark | $0.6038 | $0.875 | 1.4 倍 |
| grok-4.7 | $1.8002 | $2.00 | 1.1 倍 |

其余 25 个 MATCH。**这些不一致不是随机噪声**：`gpt-5.6-*` 系列全是「提案要给折扣、计费仍按官方挂牌」，说明发布后又被批量写回挂牌值（或发布被并发覆盖）。

### 11.3 三个工程补丁（按优先级）

| # | 补丁 | 说明 | 工作量 |
|---|---|---|---|
| P1 | **发布后校验** | `PublishPricingProposal` 提交后回读 expr，断言 `p *` 系数 == 提案价，不等则回滚并告警 | 半天 |
| P2 | **保留表达式结构** | 当前 `pricingChangeForProposal` 把表达式重建成 `tier("base", p*x + c*y)`，**丢掉 long_context 分档、缓存价、service_tier 倍率**。应改为「按模型模板替换系数」 | 1–2 天 |
| P3 | **价目巡检报表** | 每日一张「上游成本 / 我方售价 / 毛利 / 是否偏离策略」表，偏离 >10pp 标红 | 1 天 |

P2 是根因：一旦自动发布打开（`PRICING_AUTO_PUBLISH=true`），48 个模型会被降级成两段式表达式，缓存和长上下文定价全部丢失。

### 11.4 巡检指标（建议纳入 runbook）

| 指标 | 阈值 | 含义 |
|---|---|---|
| `offer_age_hours` | > 24h 告警 | 上游报价过期，可能在用旧价卖 |
| `publish_mismatch_count` | > 0 告警 | 已发布价未生效 |
| `gross_margin_bps` | < 6000 告警 | 综合毛利跌破 60% |
| `model_without_offer` | > 0 告警 | 在售但无报价，无法核算成本 |
| `manual_drift_count` | > 0 周报 | 手工改了价但没走提案 |

**一句话：模型资料、上游成本、售价三者必须由同一条链路驱动。现在缺的是「发布后校验」和「对外展示联动」，不是再建一套系统。**
